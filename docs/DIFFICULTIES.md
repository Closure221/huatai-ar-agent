# 困难清单与分工说明（2026-08-24）

> 按「我能自动完成 / 需用户配合 / 只能用户自己做」三档划分。随项目推进持续更新。

## 一、可能遇到的主要困难

### 1. 技术类
| # | 困难 | 影响 | 说明 |
|---|------|------|------|
| T1 | 政治内容审核精度 | 高 | 政治表述高度敏感，通用敏感词库 + 通用 LLM 无法保证准确，需定制规则与人工兜底 |
| T2 | AR 渲染质量（光照/遮挡） | 中 | 虚拟内容与真实场景融合的光照匹配、遮挡处理是 AR 经典难题，需反复调参 |
| T3 | 算力受限 | 中高 | OCR/检测/AIGC/渲染均吃 GPU；无显卡则推理慢、生成质量降级 |
| T4 | AIGC 素材风格一致性 | 中 | 文生图/文生视频多张之间风格漂移，需 LoRA 微调或统一 prompt 模板 |
| T5 | LLM 分镜输出不稳定 | 中 | 分镜 JSON 结构偶发不合规，需 Schema 强约束 + 校验重试 |
| T6 | OCR 在复杂场景（竖排/反光/倾斜） | 中 | 校园展板拍摄角度差、光线差时识别率下降 |
| T7 | 视频合成耗时 | 低中 | 多镜头合成 + 编码耗时长，需任务队列异步处理 |

### 2. 资源与合规类
| # | 困难 | 影响 | 说明 |
|---|------|------|------|
| R1 | 真实校园场景素材获取 | 中 | 需要真实宣传栏/展板照片或视频，涉及拍摄许可 |
| R2 | 大模型/AIGC 服务账号或部署 | 中 | 本地部署需下载大模型权重（数 GB~数十 GB），或用云 API（需账号与费用） |
| R3 | 内容合规责任边界 | 高 | 最终成片的政治正确性责任在用户/团队，AI 只做辅助审核 |

### 3. 项目类
| # | 困难 | 影响 | 说明 |
|---|------|------|------|
| P1 | 华泰杯赛制与评审标准未确认 | 中 | 交付物形态（演示视频/答辩/报告）取决于赛制 |
| P2 | 团队分工与节奏 | 中 | 2-5 人并行开发需接口先行，否则联调成本高 |
| P3 | 演示准备 | 低 | 现场演示需提前备好脚本与素材，避免设备/网络翻车 |

## 三、需要你配合我完成的

| 项 | 你需要提供 |
|----|-----------|
| 算力 | 一台带 NVIDIA GPU 的电脑（≥8GB 显存），或允许我用云 GPU 按需租用；无 GPU 则接受降级方案 |
| 模型与服务账号 | 大模型 API Key（或帮我下载/部署开源模型）、AIGC 服务账号（如有预算用云端 SD/视频模型） |
| 真实场景素材 | 校园宣传栏、展板、红色文化阵地的照片/视频（手机拍摄即可），标注大概位置 |
| 环境访问 | 允许我在你电脑上安装 Python 环境、Docker、FFmpeg、Unity 等依赖 |
| 决策拍板 | 技术选型取舍（如：本地部署 vs 云 API、Unity 深度渲染 vs FFmpeg 轻量合成） |
| 反馈验证 | 每阶段给你 demo 后，你确认是否符合预期、指出问题 |

## 五、建议的推进节奏

1. **第一步（现在）**：你确认赛制与截止时间 → 我按赛制细化里程碑
2. **第二步**：你提供环境（GPU / API Key / 拍摄素材）→ 我搭可运行的最小链路「脚本 → 分镜 → 简单 AR 合成」
3. **第三步**：逐模块深化 + 每阶段 demo 给你验证
4. **第四步**：演示视频与答辩材料配合你准备
